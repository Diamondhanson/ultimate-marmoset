# Going live — plug in your keys

The site already runs fully in **preview mode**: sample monkeys, working pages,
working forms, and a preview dashboard login. To make it real you create two
free accounts, copy a handful of values into `.env.local`, and everything
switches over automatically — **no code changes**.

---

## 1. Supabase (database, admin login, photo storage)

1. Go to <https://supabase.com/dashboard> → **New project**. Pick any name
   (e.g. `ultimate-marmoset`), set a strong database password, choose a region
   near you.
2. When the project is ready, open **SQL Editor → New query**, paste the whole
   contents of [`supabase/schema.sql`](supabase/schema.sql), and press **Run**.
   This creates every table, the security policies, the photo storage bucket,
   and the 10 sample listings.
3. Create your admin login: **Authentication → Users → Add user → Create new
   user**. Use the email you'll sign in with (it must match `ADMIN_EMAIL` in
   `.env.local`) and a strong password. Tick **Auto Confirm User**.
4. Recommended: **Authentication → Sign In / Up → disable "Allow new users to
   sign up"** — only you should ever have an account. (The app also refuses any
   login that doesn't match `ADMIN_EMAIL`, so this is belt-and-braces.)
5. Copy your keys from **Project Settings → API keys**:
   - Project URL → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon` / `publishable` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` / `secret` key → `SUPABASE_SERVICE_ROLE_KEY`

## 2. Resend (reservation + contact emails)

1. Sign up at <https://resend.com> and create an API key at
   <https://resend.com/api-keys> → `RESEND_API_KEY`.
2. That's enough for testing: with the default sandbox sender
   (`onboarding@resend.dev`), Resend delivers **only to your own account
   email** — so sign up with the same address you put in `NOTIFICATION_EMAIL`
   and notifications land in your inbox immediately.
3. Before launch (recommended): verify your own domain under **Domains** in
   Resend, then change `RESEND_FROM_EMAIL` to something like
   `Ultimate Marmoset <hello@yourdomain.com>`. That removes the sandbox limits
   and lets customers receive their confirmation emails too.

## 3. Fill in `.env.local`

Copy `.env.example` to `.env.local` and fill it in:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
SUPABASE_SERVICE_ROLE_KEY=eyJ...
RESEND_API_KEY=re_...
RESEND_FROM_EMAIL=Ultimate Marmoset <hello@yourdomain.com>
NOTIFICATION_EMAIL=you@yourdomain.com
ADMIN_EMAIL=you@yourdomain.com
```

Restart the dev server (`npm run dev`). Done — the nursery now reads from
Supabase, reservations and messages are saved **and** emailed, the dashboard
uses your real Supabase login, and photo uploads go to Supabase Storage.

## How the two modes work

|  | Preview mode (no keys) | Live mode (keys filled in) |
|---|---|---|
| Listings | Built-in sample monkeys | `monkeys` table in Supabase |
| Reservations / contact forms | Accepted, shown as success, logged to the server console only | Saved to Supabase **and** emailed to `NOTIFICATION_EMAIL` |
| Reviews | Built-in samples | Submitted by visitors, approved by you in the dashboard |
| Dashboard login | Any email + `ADMIN_PREVIEW_PASSWORD` (default `preview`) | Supabase email/password, restricted to `ADMIN_EMAIL` |
| Adding/editing monkeys | Disabled (friendly error) | Full CRUD + photo upload to Supabase Storage |

## Optional: Google Analytics & Google Ads

Leave the `NEXT_PUBLIC_GA_*` / `NEXT_PUBLIC_GOOGLE_ADS_*` variables empty and
no tracking script loads at all. Fill them in and GA4 page views plus
`reservation_submitted` / `contact_submitted` conversions start reporting
automatically.

- [ ] Replace the placeholder phone, email, and social links in [`lib/site.ts`](lib/site.ts)
- [ ] Confirm the cancellation notice period in `lib/site.ts` (`rescheduleNotice`, currently 24 hours)
- [ ] Set `site.url` in `lib/site.ts` to the real domain (used by SEO tags and the sitemap)
- [ ] Delete the 10 sample monkeys in **Dashboard → Monkeys** and add real listings with real photos
- [ ] Verify your domain in Resend and update `RESEND_FROM_EMAIL`
- [ ] Deploy (e.g. Vercel) and add the same environment variables in the hosting dashboard

## Link previews (Open Graph)

Sharing the home page or any monkey's page into Facebook, WhatsApp, iMessage,
X or LinkedIn produces a large image card. Those images are generated by the
site itself, so they always match the current listing — price, age and status
included — with no image editing.

Two things to know:

1. **They only resolve on a real, public domain.** Social networks fetch the
   image from the URL in `og:image`, so nothing renders from `localhost` or a
   password-protected preview deployment.
2. **`site.url` must match the live domain.** It is the base for every absolute
   URL in the page head.

Once deployed, test with the official debuggers — they also let you clear a
cached preview after you change a photo or price:

- Facebook / WhatsApp: <https://developers.facebook.com/tools/debug/>
- X: <https://cards-dev.x.com/validator>
- LinkedIn: <https://www.linkedin.com/post-inspector/>
